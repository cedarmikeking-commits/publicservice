# V72 工程重构说明

## 目标和迁移原则
重新组织整个公服平台的工程目录；**不减少任何业务页面、功能脚本、数据文件，不改变任何业务流程**。

## 工程结构
- `index.html`：完整公共服务官网入口，支持双击。
- `server.mjs`：项目唯一开发/静态服务器；旧 URL 兼容映射。
- `src/apps/`：完整原业务应用原样迁移。
  - `site`：公共官网、快速八题
  - `auth`：登录、注册及角色入口
  - `personal`：个人端与能力档案
  - `institution`：院校端
  - `area`：区域与总部经营业务
  - `assessment`：能力评价、考评点、命题、题库与报告原业务资源
  - `operations`：运营业务
  - `assets`：原共享资源和官网数据
  - `workspace`：V70 新工作台代码（原有实验模块，没有覆盖业务）
- `src/platform/routes.json`：统一入口清单（为下一步将各应用整合到单运行时预留）。
- `docs/MIGRATION_INVENTORY.json`：逐文件 SHA256 迁移凭证。
- `tests/verify.mjs`：静态完整性和引用检查。
- `docs/history`：旧版发布记录，方便追溯。

## 兼容说明
源码中的 HTML/JS/CSS 及业务数据保持字节级一致，以免迁移时改变业务流。
历史页面中使用的 `../` 相对链接仍成立，因为原各模块的兄弟目录关系未改变。
原 `/area/`、`/assessment/`、`/auth/` 等绝对旧 URL 在本地 HTTP 服务中映射到 `src/apps/`。

## 已知限制
本次完成**工程目录结构重建及全部源码原样迁移**；不等于把原本独立的经营后台和测评后台合并成同一个 JavaScript 应用。后者涉及大型业务代码拆分、统一权限服务及实际浏览器回归，不能在保持每一行旧业务代码不变的同时伪称已经完成。
